ENGINEERING CASE STUDY

Flow CLI

C · Bash · Zsh · macOS · Linux

Project Background

While developing Minishell with a teammate, I kept rerunning the same command sequences to check for regressions. I started Flow independently so I could record reliable command sequences, save them under names, and replay them instead of typing everything again.

Technical Implementation

  • Shell integration: Capturing interactive commands through Bash and Zsh hooks.
  • Workflow recording: Recording command sequences and saving reusable named workflows.
  • Management: Listing, organizing, copying, combining, and restoring workflows.
  • Replay: Running saved command sequences in the user’s shell environment.
  • Cross-platform support: Supporting macOS and Linux environments, installation scripts, and shell differences.
  • Reliability: Handling arguments, invalid input, workflow state, and filesystem-related operations.

Engineering Challenges

Bash and Zsh use different command capture mechanisms, and replay depends on directory context, execution order, environment configuration, and safe handling of failures.

What I Learned

Flow taught me to recognize and solve inefficiencies in my own development workflow—and consider usability, documentation, portability, and test coverage as part of engineering.

Future Direction

My longer-term vision is to let developers import and share reviewed workflows, check prerequisites, preview actions, and automate repeatable development setups with better safety controls.

The portfolio’s Flow demo is a browser simulation. It never runs shell commands or Git operations on visitors’ computers.
