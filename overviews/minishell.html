ENGINEERING CASE STUDY

Minishell

C · Unix · POSIX · Readline · Make

Project Background

Minishell is a collaborative 42 Bangkok project where we implemented a Unix-like command interpreter in C. I wanted to understand how a shell connects user commands to the operating system. A shell runs in user space and uses system calls to request services from the kernel, including creating processes, executing programs, and communicating through pipes.

Technical Implementation

  • Parsing: Tokenization, environment-variable expansion, quoting, command structures, and redirections.
  • Kernel interfaces: Using fork(), execve(), and waitpid() to create, execute, and manage child processes.
  • Pipelines and file descriptors: Using pipe() and dup2() to connect standard input and output across commands.
  • Built-in commands: Supporting cd, echo, pwd, env, export, unset, and exit.
  • Signals and memory: Handling terminal interruptions, allocated resources, and cleanup.

Engineering Challenges

Parsing, expansion, redirection, and execution are tightly connected. Small changes can affect many command scenarios, so systematic regression testing and careful resource handling were essential.

What I Learned

I developed a stronger understanding of the boundary between user-space applications and the kernel, inter-process communication, debugging, and collaborative systems development. The repeated need to rerun tests after changes also inspired my independent Flow CLI project.

Minishell uses operating-system APIs; it does not implement kernel code.
